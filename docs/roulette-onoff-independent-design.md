# 룰렛 기록 on/off — 위플랩 독립 운영 설계안 (개정)

작성: 2026-07-05 · 상태: **Phase 1·2 구현·배포 완료(2026-07-05)** · 기존 `roulette-usage-overlay-design.md`의 결정 1·2를 개정한다.
기본값은 (A) 확정: 안 만진 룰렛은 최초 위플랩 상태로 시작, sy가 한 번 만지면 그 뒤 위플랩과 무관하게 고정.

## 1. 배경 — 지금 문제
- **증상**: 룰렛 관리에서 켜져 있는 룰렛을 꺼도, 얼마 뒤(위플랩표가 다시 수집되면) 다시 켜져 있다.
- **원인(코드 확인)**: 내 on/off 설정을 "캡처 **버전 번호** + 그 버전의 그룹/상품 인덱스"에 못박아 저장한다(`catalog_usage_updated` payload = `{ catalogVersion, overrides:{ "g3":false } }`). 위플랩표가 한 번 다시 읽히면 **내용이 같아도 새 버전이 생기고**(`saveCatalogForStreamer`에 중복 차단 없음), 새 버전엔 내 설정이 없어 위플랩 원래값(켜짐)으로 리셋된다.
- **범위 확인**: 저장→DB→새로고침→렌더를 추적한 결과, **같은 버전 안에서는 정상 저장·복원**된다. 버전이 갈릴 때만 리셋 → 근본 원인은 "버전에 묶인 저장 키".

## 2. 방향 결정 (2026-07-05 sy 확정)
**기록 여부 on/off는 위플랩과 무관하게 우리(룰렛 관리표)가 직접 소유·운영한다.** 위플랩의 on/off는 "위플랩에선 꺼짐" **참고 배지로만** 표시하고, 판정·지속의 기준으로는 쓰지 않는다.

## 3. 핵심 전환 — "버전"이 아니라 "룰렛 내용"에 붙인다
- (기존) 키 = `버전7 · g3` → 버전 바뀌면 무효
- (개정) 키 = 룰렛/상품의 **내용 지문**
  - 상품 단위: `금액대 + 상품명(+확률)` 정확 일치
  - 룰렛(그룹) 단위: 그 룰렛의 **상품명 집합(지문)** — 앱이 이미 쓰는 자카드 ≥ 0.5 유사매칭과 동일 규칙
- 효과: 위플랩표가 새 버전으로 들어와도 **"같은 룰렛"이면 내 off가 자동으로 따라온다.** sy가 매번 다시 끌 필요 없음.

## 4. 재현성은 그대로 유지 (트레이드오프 없음)
- 저장은 지금처럼 **append-only 스냅샷**(저장 시각 자동 기록)을 유지한다.
- 평소 화면·판정은 "가장 최근 설정"을 적용하고, 과거 판정 재현이 필요하면 "그 시점 이전의 최근 스냅샷"을 읽어 재현한다.
- → **독립 운영 + 검증실 재현성 동시 만족.** (재현성 포기 안 함)

## 5. 함께 넣는 것 — 중복 캡처 차단
- `saveCatalogForStreamer`가 새 버전을 만들기 전에, 직전 버전과 **내용 지문이 동일하면 새 버전을 만들지 않고 기존 버전을 재사용**한다.
- "동일" 기준 = `금액대 + 상품명 + 확률`. **위플랩 on/off 상태는 지문에서 제외**(우리 판단 대상이 아님).
- **원본 증거(raw_imports)는 계속 남긴다** — "논리 버전"만 재사용하고 증거는 보존.
- 참고: 3번(내용 기준 저장)만으로도 버그는 사라진다. 이 항목은 "버전 이력을 깔끔하게 유지"하는 보조 개선.

## 6. 확인 필요한 1가지 — 아직 손 안 댄 룰렛의 기본값
sy가 아직 켜고/끄고를 정하지 않은 룰렛은 기본을 뭐로 둘까?
- **제안 (A) [추천]**: 최초에는 위플랩 상태대로 시작(위플랩 꺼짐→꺼진 채로, 켜짐→켜진 채로). 단 **sy가 한 번이라도 만지면 그 뒤론 위플랩과 무관하게 내 값 고정.** → 수십 개를 일일이 끌 필요 없음. 최초 기본값에만 위플랩을 참고할 뿐 판정·지속엔 안 쓰므로 "독립" 취지 유지.
- (B): 위플랩 완전 무시. 안 만진 룰렛은 전부 "켜짐(기록함)"이 기본. → 완전 독립이지만 위플랩에서 안 돌리는 룰렛까지 기록 대상이 됨(아마 원치 않음).

## 7. 안 건드리는 것
판정 엔진 `reconcileResults`, DB 스키마, 확장(수집) 구조, 인증, raw_imports·과거 판정 기록. 저장은 기존 `audit_logs` 오버레이 패턴 재사용(스키마 변경 없음).

## 8. 구현 단계 (승인 후)
1. **저장/읽기**: on/off를 내용 지문 키로 저장 + "최근 매칭 우선" 해석(`applyCatalogUsage` 확장, CatalogManager 내부 키 교체)
2. **중복 캡처 차단**: `saveCatalogForStreamer` 지문 비교
3. **관리 UI**: 토글·배지 UX는 그대로, 내부 키만 교체
4. **검증**: "오버라이드 0개 = 기존 판정과 100% 동일" 회귀 + 실제 재현 테스트 + tsc/lint/build + 배포 후 실데이터 확인

## 9. 리스크와 대응
| 리스크 | 대응 |
|---|---|
| 룰렛 내용이 조금 바뀌면 다른 룰렛으로 인식돼 설정 유실 | 자카드 ≥ 0.5 유사매칭(앱 기존 규칙) + 상품 단위는 이름 정확일치 |
| 같은 금액대(예: "33" 4개) 혼동 | 금액대가 아니라 **상품 지문**으로 식별 → 지문 다르면 개별 룰렛으로 취급 |
| 과거 판정 재현이 흐려짐 | append-only 시각 스냅샷 유지로 시점 복원 |
