# 정가기록(시그니처 후원) — 설계안

작성: 2026-07-03 · 상태: **sy 승인 대기** · 구현 전 문서

## 1. 개념

스트리머마다 "시그니처 후원 갯수"(예: 1000개, 5000개)를 지정한다. 시청자 후원의 풍선 갯수가
지정된 갯수와 일치하면 **정가기록**으로 남는다 — 룰렛 확률로 얻는 업보가 아니라, 갯수 자체가
의미인 고정가 업보. 룰렛기록과 표기가 명확히 구분되어야 한다.

## 2. 확인된 사실 (2026-07-03 코드 확인)

- 확장프로그램은 룰렛 결과만이 아니라 **위플랩 알림 리스트 테이블 전체**를 캡처한다
  (upbo-beta/extension/content.js: `table.alertlist_table` 행 수집). 즉 룰렛을 돌리지 않은
  순수 후원도 갯수(donationAmount)와 함께 **이미 수집되고 있다** → 자동 판정 가능.
- 원본은 raw_imports 에 전부 보관 중(불변). 룰렛에 안 걸린 행은 현재 "무시" 판정될 뿐 데이터는 있다.
- upbo_entries 테이블은 donation_amount/amount_range_label/probability(널 허용) 등 필요한 칸을
  이미 갖고 있다 → **스키마 변경 없음**.

## 3. 데이터 설계 — 스키마 변경 없음

### 시그니처 갯수 설정 (스트리머별)
- audit_logs `action="signature_counts_updated"`, payload `{ counts: number[] }`, 최신 1건이 현재 설정.
- 관리자 새 탭 "정가 설정": 기본 입력칸 5개 + "갯수 추가" 버튼(5개 초과 무제한), 빈 칸은 무시.
  기존 extension 토큰 인증 + 단계별 저장 문구(테마/홍보/사용설정과 동일 UX).

### 정가기록 저장
- **upbo_entries 행 재사용** (룰렛 기록과 같은 테이블 → 배송/보유 계산에 자동 합류):
  - `source_key`: `fixed:{fanId}:{donateTimeText}:{donationAmount}` — **후원 1건당 1기록**.
    11연차처럼 한 후원이 여러 행으로 잡혀도 정가기록은 1개만 생긴다(중복 방지).
  - `item_name`: `"정가 {N}개"` (상세 상품은 배송관리 메모로 수기 작성)
  - `probability`: 0, `catalog_version`: null, `amount_range_label`: `"정가"`
  - 정가 여부 판별 = source_key 가 `fixed:` 로 시작 (+ amount_range_label "정가")
- 기존 createSourceKey 규칙/유니크 제약은 건드리지 않는다(정가는 자체 prefix 키).

### 정가 전용 메모
- audit_logs `action="fixed_price_note_updated"`, payload `{ entrySourceKey, noteText }`, 기록별 최신 1건.
- 배송관리 화면에서 정가기록 항목 아래 메모 입력칸(수기 상품목록 작성용) + 저장.

## 4. 판정 연결 — reconcileResults 무수정

- applyResultsForStreamer / previewResultsForStreamer 에 **별도 정가 패스** 추가:
  캡처의 정규화된 행들에서 `donationAmount ∈ 시그니처 갯수` 인 후원을 골라
  (후원 단위로 묶어) 정가 entry 를 만든다. 룰렛 판정 파이프라인(reconcileResults)은 그대로.
- **회귀 안전망**: 시그니처 갯수를 하나도 설정하지 않은 스트리머는 동작이 기존과 100% 동일.
- 적용 시점: **새로 반영되는 캡처부터**. 과거 배치 소급은 범위 밖(원하면 추후 별도
  "과거 후원 재검사" 버튼으로 2단계 — raw_imports 재실행 패턴 재사용 가능).

## 5. 화면 — 룰렛기록과 표기 차별화

- **팬 화면(업보 목록/획득 기록)**: 정가기록에 `정가` 배지(포인트색 계열, 룰렛의 % 표기 대신
  "정가 5000개" 형태). 보유 계산(computeHoldings)에는 그대로 합류하므로 목록에 자연스럽게 나타난다.
- **배송관리**: 시청자 업보목록에 정가기록 표시(동일 배지) + 그 아래 **정가 메모칸**
  (이 정가 업보로 줄 상품목록 수기 작성, 토큰 저장, 저장 문구 표시).
- **관리자 "정가 설정" 탭**: 갯수 5칸+추가 버튼, 현재 설정 표시, 저장.

## 6. 구현 단계

1. 데이터+API: 시그니처 설정 get/set + 정가 메모 get/set + 라우트 2개 (audit_logs 패턴)
2. 판정 패스: apply/preview 에 정가 entry 생성 (중복 키·후원 단위 묶기 포함)
3. 관리자 "정가 설정" 탭 UI
4. 팬/배송 표기 차별화 + 배송관리 정가 메모 UI
5. 검증: tsc/lint/build + 임시 QA 페이지 + "시그니처 미설정 = 기존 동일" 회귀 확인 → 배포(승인)

## 7. 결정 필요 (기본값 제안)

1. **룰렛도 돌아간 후원이 시그니처 갯수와 일치하면?** → 제안: 정가기록도 **함께** 남긴다
   (스트리머가 지정한 갯수인 이상 정가로 취급; 겹치는 갯수를 피하는 건 스트리머 운영 재량).
2. **소급 적용**: 이미 수집된 과거 후원 → 제안: 이번엔 새 캡처부터, 소급 재검사는 2단계.

## 8. 건드리지 않는 것

reconcileResults 로직, createSourceKey 규칙, DB 스키마, 확장프로그램, raw_imports, 기존 룰렛 판정 기록.
